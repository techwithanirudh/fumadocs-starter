## Project Overview
Next.js 16 App Router documentation site built with Fumadocs. Combines MDX content, OpenAPI-generated API reference pages, and an AI chat assistant backed by the Vercel AI SDK.

- TypeScript strict mode with path aliases (`@/*`, `@/public/*`)
- Tailwind CSS v4 with PostCSS; global tokens in `src/styles/globals.css`
- Radix UI primitives + shadcn/ui components in `src/components/ui`
- Always use Context7 MCP when needing library/API documentation or configuration steps

## Commands
- Install: `bun install`
- Dev: `bun dev`
- Build: `bun run build` (runs `scripts/pre-build.ts` → Next build → `scripts/post-build.ts`)
- Types: `bun run typegen` (runs `fumadocs-mdx && next typegen`), `bun run typecheck`
- Lint/format: `bun run check` · fix: `bun run check:write` · unsafe fix: `bun run check:unsafe`
- QA: `bun run check:links`, `bun run check:spelling`

## Architecture

### Content pipeline
- Author MDX in `content/`; never edit `.source/` (generated by `fumadocs-mdx` on `postinstall`)
- `src/lib/source.tsx` — single `source` export built with `loader(multiple({...}))` combining:
  - `docs` collection from `fumadocs-mdx:collections/server`
  - `openapi` collection from `fumadocs-openapi/server` pointing at `content/docs/api-reference/openapi.yml`
- The `source` object is used everywhere: `source.getPage()`, `source.getPageTree()`, `source.generateParams()`

### Route structure
- `src/app/(home)/` — marketing/landing pages with `HomeLayout`
- `src/app/docs/[[...slug]]/page.tsx` — catch-all docs page; renders OpenAPI pages via `<APIPage>` and MDX pages via the loaded `Mdx` component
- `src/app/docs/layout.tsx` — `DocsLayout` (notebook style) with sidebar tabs colored per top-level section
- `src/app/api/chat/route.ts` — AI chat endpoint (POST); uses `streamText` with `gpt-5-mini`, two tools: `searchDocs` and `getPageContent`
- `src/app/api/proxy/route.ts` — proxies OpenAPI try-it requests
- `src/app/api/search/route.ts` — Fumadocs search endpoint
- `src/app/og/[...slug]/` — OG image generation
- `src/app/llms.txt/`, `src/app/llms-full.txt/`, `src/app/llms.mdx/` — LLM-readable content endpoints

### Shared layout config
`src/lib/layout.shared.tsx` exports `baseOptions()`, `linkItems`, `logo`, and `title` — used by both home and docs layouts to stay in sync.

### AI chat feature
- Entry point: `src/app/api/chat/route.ts`
- Prompts assembled in `src/app/api/chat/utils/prompts/` (`core.ts`, `directives.ts`, `examples.ts`, `tools.ts`, `llms.ts`)
- Tools: `searchDocs` (wraps Fumadocs search, streams results via `writer`) and `getPageContent` (fetches a page's MDX)
- UI components in `src/components/fumadocs/ai/` — `<AISearch>`, `<AISearchPanel>`, `<AISearchTrigger>`, message rendering, shimmer, tool display

### Environment
- Validated in `src/env.ts` via `@t3-oss/env-nextjs` + zod; `next.config.ts` imports it at startup
- `SKIP_ENV_VALIDATION=true` for CI environments without secrets
- `bun run with-env` prefix loads `.env` via `dotenv-cli`

## Key conventions
- Prefer `cn` from `src/lib/utils.ts` (or `src/lib/cn.ts`) for merging Tailwind classes
- Path aliases over relative imports; avoid barrel files — import from the source module directly
- `fumadocs-mdx:collections/*` is the virtual import alias for `.source/*`
- Use `@/lib/metadata.ts` (`createMetadata`, `baseUrl`, `getPageImage`) for all page metadata
- `src/lib/page-tree.ts` and `src/lib/layout.shared.tsx` for any navigation/tree customization
- Extend shadcn/ui components rather than copying them
- Run `bun x ultracite fix` before committing
